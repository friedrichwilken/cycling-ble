# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

Nothing has been published to crates.io yet — everything below is
pre-release.

### Added

- Contract tests (`tests/contract/`): golden byte vectors asserting the
  complete parsed value for every characteristic, the truncation error
  contract, and a never-panic test over exhaustive short payloads and
  fixed-seed random payloads. Append-only within a breaking version (see
  `tests/contract/README.md`).
- `STABILITY.md`: what the stable public API covers, behavioural
  guarantees, MSRV policy, and the versioning rule.
- Public API snapshot `public-api.txt` (generated by `cargo public-api
  --all-features`), `just api` / `just api-check`, and a `public-api` CI
  job that fails when the API drifts from the snapshot.
- Unit and resolution stated in the doc comment of every public field.
- Initial `cycling-ble` crate: pure byte-parsing (no BLE transport
  dependency) for four cycling GATT characteristics — Cycling Power
  Measurement (0x2A63, including pedal power balance), Heart Rate
  Measurement (0x2A37), CSC Measurement (0x2A5B), and FTMS Indoor Bike
  Data (0x2AD2) — plus a `revolutions_per_minute` helper for turning two
  consecutive revolution-counter readings into cadence/speed.
- `justfile` with filtered `check`/`build`/`test`/`clippy`/`fmt`/`clean`
  targets.
- Zwift Click controller support (`zwift_click` module): handshake
  request, button-state parsing (`ClickButtonState`), and battery/idle
  frame handling for the non-standard Zwift accessory service.
  **Experimental** — gated behind the opt-in `zwift-click` feature (not
  in `default`) and not documented in `README.md` yet.

### Changed

- Version 0.2.0. All public result structs and enums are now
  `#[non_exhaustive]` (`CyclingPowerMeasurement`, `PedalPowerBalance`,
  `PedalPowerBalanceReference`, `MinMax`, `power::WheelRevolutionData`,
  `power::CrankRevolutionData`, `HeartRateMeasurement`, `CscMeasurement`,
  `csc::WheelRevolutionData`, `csc::CrankRevolutionData`,
  `IndoorBikeData`, `ClickButtonState`). Breaking: they can no longer be
  built with struct literals or matched exhaustively outside the crate.
  `ParseError` is unchanged.
- `just check`/`build`/`test`/`clippy` pass extra arguments through to
  cargo (e.g. `just test --features zwift-click`).

### Fixed

- `zwift_click::parse` — the button-state opcode, byte layout, and
  press-encoding were all wrong, verified against a live capture from real
  Click hardware (2026-08-14): the opcode is `0x23` (not the previously
  assumed `0x37`), the two paddles share one status byte at offset 3 (not
  two separate whole bytes), and presses are signaled by individual bits
  going low (`0x20` for "+", `0x02` for "-") rather than a whole byte
  going to `0x00`. The crate previously never detected a real button press
  on actual hardware. Also fixed `examples/zwift_click.rs`'s device
  matching, which filtered on the wrong service UUID (the one exposed
  post-connection, not the one actually advertised) and so never found a
  real Click either.
